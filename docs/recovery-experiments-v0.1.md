# Recovery experiments

The author has explicitly requested recovery of the earlier working writing
procedure, followed by repeated code-generated trials and Pangram observations
until the target result is reached. This extends the authorization to run new
declared experiments; it does not turn a detector result into author approval.

## Recovered evidence

The private RUN_015 record retains an actual expression input with all 84
original v0.4 spoken excerpt texts, all 18 rules, full approved P006, and three
additional spoken candidates. The original excerpts total 960 words. Eight
were preselected in its plan while the other 76 remained available to the
writer. Rules and original excerpts used compact fields; the expression input
did not contain the full original source-transcript table. Written P006 spans
also had explicit paragraph/layer applications.

This is evidence of earlier prompt contents. RUN_015's retained detector status
is `not_run`; the separately preserved P006 and RUN_004 successes must not be
misattributed to it. Its saved orchestration instruction and input are not an
original HTTP request envelope for those other successful attempts.

## First comparison

Keep the current subject source, v0.4 ledger, model configuration, P006,
paragraph grouping, and repair budgets identical between the first two new
trials. Both use the opt-in full-corpus projection, with complete recorded
source contexts available and unchanged grounding relationships.

1. Full-corpus baseline: existing subject intent and all 84 original examples.
2. Recovered expression contract: same inputs plus the saved directions to
   write connected prose, put necessary uncertainty within claims, provide
   concrete context, and avoid formulaic contrasts, canned transitions,
   padding and repeated qualification endings. This is an experimental
   instruction derived from the recovered record, not a ledger rule change.

The richer source-context projection is explicitly different from RUN_015's
compact input. If the first comparison does not recover the target, the next
evidence-supported comparison may test compact presentation of the same
authentic corpus or explicit passage-level written-example applications.
Declare each change before generation; never edit an active run's inputs.

## Execution and evidence

`verification/run_recovery_trial.py` calls the existing `Execution` and loop
owners. It is an experiment command, not a second lifecycle implementation.
Every trial binds its committed configuration, code, ledger, source hashes and
prompt templates. Each exact provider request is journaled before transmission.
All candidates, findings, repairs and detector responses remain preserved.

The author's delegation permits operational construction closure after current
passing review and bounded repairs of diagnosed expression defects. The driver
does not grant final author approval, waive an unresolved construction defect,
change rules, or modify detector thresholds. An unvalidated draft may be
observed separately only when explicitly requested and labeled accordingly.

Pangram remains outside the generation context. A score can inform selection of
the next declared process experiment, but is not inserted into the writing
prompt, and unchanged text is not resubmitted to seek a favorable score.

A qualifying candidate must preserve the source's claims and uncertainty, pass
the current four-layer assessment and satisfy the unchanged detector gate on
the exact same text. Report the number of attempts and the actual raw result.
After a qualifying candidate, one independent generation with the same working
configuration can test repeatability. Author voice and substance approval
remain for the author.

The first two observations recovered the requested detector target. Their
canonical writing states remain unchanged, with one linguistic finding each.
The independent confirmation did not reproduce that detector result. No trial
has both current writing and detector gates passed; none has final author
approval. Exact fractions, layer states, prompt counts, commits and text hashes
are recorded in [the verification metadata](../verification/recovery-live-results-v0.1.json).

Full-context expression used applicable rule subsets (nine rules in trial 001,
seven in trials 002 and 005), all 84 excerpts and all 35 recorded source
contexts. Compact expression used all 18 rules and all 84 excerpts without the
full source-context table. Thus those comparisons changed both context
inclusion and rule-catalog presentation. Individual generated outputs do not
isolate one cause for the detector differences.

The exact texts, every provider request and response, all paragraph versions,
review findings, detector records and stable database snapshots are retained
in the private recovery evidence package. Public metadata contains no
manuscript text, exemplar text, private prompts or credentials.
